# Alpha validation report

- GhostDeploy version and full tested commit
- Odoo series and exact version
- PostgreSQL major and exact server version
- Ubuntu version
- Runner class and disposable host type
- Deployment result and exact dispatch commit
- Recovery result, including whether restored login, original record and attachment hash passed

## Reproduction and results

Describe the minimum repeatable steps, including the success run, intentional second-database failure and blocked retry. Include safe Actions run links or report anonymized job conclusions and phases. Record the configured branch restriction, reviewer approval if enforced, same-environment concurrency, host-key pin and forced-command denial. Use synthetic database aliases A, B and C. Mark any unchecked item pending.

## Sanitized errors

Paste only the short lines needed to diagnose the issue. Remove addresses, hostnames, usernames, private paths and secret values. Share neither credentials nor dumps, customer data, full logs, full configuration or authorization files. Send suspected vulnerabilities privately using the [security reporting process](../../SECURITY.md).
